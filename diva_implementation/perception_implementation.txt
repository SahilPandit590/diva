1. ARCHITECTURAL CHECKPOINT COMPLIANCE MATRIX
================================================================================

[x] Checkpoint 1: Input Reception and Validation
    - Multi-channel ingress: CLI, WebSocket, HTTP REST, Web Scraper, Inter-Engine events.
    - UUIDv7 generation (time-ordered, monotonic, collision-free).
    - Source, session, and nanosecond UTC reception timestamps attached at the physical boundary.
    - Strict validation: payload size bounds (max 256KB per turn), UTF-8 encoding verification.
    - Safe rejection of malformed or oversized payloads with structured error reporting.
    - Raw input preserved byte-for-byte in immutable `RawInputReference`.

[x] Checkpoint 2: Input Type Detection
    - Modality identified: `TEXT` (Phase 1), with structural hooks for `AUDIO`, `IMAGE`, `VIDEO`.
    - Encoding detection with automatic repair (UTF-8 strict with CP1252/Latin-1 recovery).
    - Format classified: `PLAIN_TEXT`, `MARKDOWN`, `JSON_PAYLOAD`, `CODE_SNIPPET`.
    - Ingress source category: `USER_DIRECT`, `SYSTEM_NOTICE`, `TOOL_OUTPUT`, `INTER_ENGINE`.
    - Common `BaseModalityProcessor` interface ensures uniform downstream handling.

[x] Checkpoint 3: Text Normalization
    - Canonical Unicode NFKC normalization and line-ending standardization (`\r\n` -> `\n`).
    - Stripping of unprintable control characters while preserving formatting tabs and code indentation.
    - Raw input preserved without mutation.
    - Bidirectional character offset mapping (`OffsetMap`) maintained between normalized and raw text.
    - Non-destructive guarantee: emojis, quotes, technical syntax, and punctuation nuances preserved.

[x] Checkpoint 4: Content Extraction
    - Syntactic segmentation into sentences, clauses, and code blocks (`TextSegment`).
    - Hybrid Named Entity Recognition (NER): Deterministic regex patterns + local GLiNER-ONNX transformer.
    - Identification of dates, times, locations, people, organizations, products, and concepts.
    - Extraction of Subject-Predicate-Object semantic triplets.
    - Syntactic qualification: negation (`is_negated`), temporal anchors, and modal qualifiers.
    - Exact character span offsets (`start_char`, `end_char`) attached to every extracted entity.
    - Extraction confidence $[0.0, 1.0]$ and method metadata (`REGEX`, `GAZETTEER`, `GLINER_ONNX`).

[x] Checkpoint 5: Context Resolution
    - Pronoun and anaphora resolution via read-only interface to Working Memory ($k$ recent turns).
    - Salience and feature-weighted scoring formula for candidate entity binding.
    - Elliptical completion: short fragmented answers anchored to prior turn questions.
    - Backlinks to preceding turn IDs (`referenced_turn_ids`).
    - Ambiguity preservation: unresolved pronouns retained with ranked candidate lists; never forced.
    - Strict read-only interaction with Working Memory (zero mutation during perception).

[x] Checkpoint 6: Intent and Speech-Act Recognition
    - Multi-class classification: Statements, Questions (WH/YN), Commands, Requests, Expressions, Greetings.
    - Primary and secondary speech-act tagging.
    - Communicative intent extraction (e.g., `DISCLOSE_FACT`, `SEEK_HELP`, `SET_BOUNDARY`).
    - Multi-intent support: allows compound messages (e.g., "I quit today; don't tell Sarah").
    - Calibrated confidence scores attached to all intent classifications.
    - Strict boundary: Communicative intent (what the speaker seeks) is never confused with Diva's internal motivations.

[x] Checkpoint 7: Semantic Interpretation
    - Literal compositional proposition extraction.
    - Pragmatic contextual interpretation incorporating active conversation state.
    - Identification of implicit references, sarcasm markers, and double entendres.
    - Generation of alternative interpretations when ambiguity is detected.
    - Explicit epistemic separation: `FACT` vs. `HYPOTHESIS` vs. `INTERPRETATION`.
    - Uncertainty preservation: missing information explicitly tagged as `UNKNOWN` rather than hallucinated.

[x] Checkpoint 8: Uncertainty Management
    - Orthogonal separation of Source Trust ($T \in [0.0, 1.0]$) and Interpretation Confidence ($C \in [0.0, 1.0]$).
    - Competing Hypotheses DAG maintained when ambiguity margin $\Delta = |C_1 - C_2| < 0.20$.
    - Bidirectional links between competing interpretations.
    - Evidence tracing: every hypothesis cites the specific text segments supporting it.
    - Clarification trigger: `requires_clarification = True` flagged for the Thought Engine.
    - Anti-Hallucination Invariant: Hypotheses never convert to established facts within Perception, regardless of confidence.
    - Uncertainty metadata broadcast to all downstream engines.

[x] Checkpoint 9: Provenance and Source Traceability
    - Ingestion origin tracked: actor ID, channel, and physical ingress endpoint.
    - Processing audit trail: transformations recorded (`transformations_applied`).
    - Character-span backlinks connecting every proposition to raw input bytes.
    - Provenance taxonomy distinguishes user claims from tool observations and Diva inferences.
    - Complete backward traversal graph available to all downstream engines.

[x] Checkpoint 10: Engine-Specific Output
    - Universal output envelope (`EngineOutputPackage`) with schema versioning.
    - Dedicated, tailored payload contracts:
      * Memory: Raw reference, character span maps, entities, triplets, provenance.
      * Thought: Pragmatic interpretations, speech acts, ambiguity DAG, elliptical anchors.
      * Emotion: Verbatim text, surface tone indicators (capitalization, punctuation), affective tokens.
      * Social Cognition: Interpersonal speech acts (promises, boundaries), social entities, candidate relations.
      * Learning: Novel vocabulary/jargon, explicit user corrections to prior knowledge.
      * Feedback: Processing telemetry, stage latencies, model confidence distributions.
    - Selective distribution prevents cognitive context bloat.
    - Provenance and uncertainty preserved in every individual package.

[x] Checkpoint 11: State and Lifecycle Management
    - Formal 8-state machine: `RECEIVED` -> `VALIDATED` -> `NORMALIZING` -> `EXTRACTING` -> `INTERPRETING` -> `PACKAGING` -> `DISPATCHED` -> `COMPLETED` (or `FAILED` / `DEGRADED`).
    - Concurrent turn processing via Python 3.12 `asyncio.TaskGroup`.
    - Ephemeral buffer management: in-flight data held in memory; zero disk allocation in Perception.
    - Downstream delivery acknowledgments tracked.
    - Safety lease: temporary buffer retained until all downstream engines acknowledge or 60-second TTL expires.

[x] Checkpoint 12: Error Handling and Recovery
    - Tiered graceful degradation:
      * Model failure -> Regex & gazetteer fallback.
      * Context retrieval failure -> Process without context; flag `DEGRADED_NO_CONTEXT`.
      * Total pipeline failure -> Deliver raw normalized text in `FALLBACK_RAW_ENVELOPE`.
    - Processing warnings and component errors logged to Feedback Engine.
    - Idempotent deduplication: BLAKE2b hash debouncing drops accidental duplicate clicks within 2 seconds.
    - Input byte preservation guaranteed even during partial component crashes.

[x] Checkpoint 13: Modality Expansion Readiness
    - Abstract `BaseModalityProcessor` interface decouples modality from core cognition.
    - Clean separation between text-specific tokenizers and modality-neutral schemas (`InputEvent`, `ExtractedEntity`).
    - Architectural specifications for Audio (Whisper + prosody) and Vision (OCR + object detection).
    - Downstream engines consume identical semantic representations regardless of input modality.

[x] Checkpoint 14: Integration and Architectural Correctness
    - Strongly typed, versioned API contracts with all 6 downstream engines.
    - Absolute ownership boundaries: Perception parses; Memory persists; Thought decides; Emotion appraises.
    - Epistemic integrity: Inferences remain hypotheses; contradictions are surfaced, not suppressed.
    - End-to-end event traceability from final action back to initial input byte.

2.2 Explicit Cognitive Boundaries (What Perception NEVER Does)
- Emotion Engine Boundary: Perception identifies surface affect markers (e.g. all-caps text, exclamation count, explicit words like "angry"); it NEVER decides Diva's internal emotional response or mood state.
- Social Cognition Boundary: Perception extracts social speech acts (e.g. apologies, requests) and mentions of people; it NEVER calculates interpersonal trust evolution, intimacy levels, or social rapport.
- Motivation & Thought Boundary: Perception extracts communicative intentions (what the speaker wants); it NEVER decides Diva's goals, motivations, reasoning strategies, or external actions.
- Memory Engine Boundary: Perception manages an ephemeral in-memory processing buffer; it NEVER owns persistent storage, retention scheduling, or consolidation.

4. STAGE-BY-STAGE PROCESSING PIPELINE & ALGORITHMS
================================================================================

4.1 End-to-End Pipeline Walkthrough
```
[Raw Bytes] 
    │
    ▼ Stage 1: Validate Ingress (<1ms)
[RawInputReference & InputEvent]
    │
    ▼ Stage 2: Normalize & Compute Span Map (<2ms)
[NormalizedInput & OffsetMap]
    │
    ▼ Stage 3: Concurrent Extract & Context Resolve (<15ms)
    ├─> [TextSegments + Hybrid NER + Triples]
    └─> [Working Memory Lookup + Coreference Resolution]
    │
    ▼ Stage 4: Semantic Interpretation (<10ms)
[Speech Acts + Pragmatic Hypotheses]
    │
    ▼ Stage 5: Uncertainty Evaluation & Calibration (<2ms)
[Ambiguity Margin + Competing Hypotheses DAG]
    │
    ▼ Stage 6: Selective Dispatch (<1ms)
[MemoryEnvelope, ThoughtEnvelope, EmotionEnvelope, etc.]
```

4.2 Algorithm Details

1. Invertible Span Mapping:
   - When text is normalized (e.g. collapsing `  ` into ` `), character offsets shift.
   - The Normalizer builds an interval offset tree:
     $$M(i) = \text{original\_index\_of}(i)$$
   - Invariant:
     $$\text{NormalizedText}[s : e] \equiv \text{OriginalRawText}[M(s) : M(e)]$$

2. Hybrid NER & Arbitration:
   - Regex patterns execute first for structured data (`DATETIME`, `PHONE`, `EMAIL`, `URL`).
   - Quantized GLiNER-ONNX executes in parallel for semantic types (`PERSON`, `ORG`, `LOCATION`, `CONCEPT`).
   - Arbitration Rule: Structured regex matches take precedence on overlapping spans; semantic model handles all general spans.

3. Salience-Based Coreference Resolution:
   - Identifies third-person pronouns.
   - Queries Working Memory for active candidate entities in recent turns.
   - Computes candidate score:
     $$S(E) = 0.35 \cdot M_{\text{gender}} + 0.25 \cdot M_{\text{number}} + 0.20 \cdot \frac{1}{\text{turn\_distance}} + 0.20 \cdot \text{Salience}(E)$$
   - Threshold Rule: If $S(E_{\text{top}}) \ge 0.75$ and $S(E_{\text{top}}) - S(E_{\text{second}}) \ge 0.25$, bind pronoun. Else, preserve candidates in `unresolved_pronouns`.

5. UNCERTAINTY MANAGEMENT & COMPETING HYPOTHESES DAG
================================================================================

5.1 Epistemic Separation of Trust vs. Confidence
- Source Trust ($T \in [0.0, 1.0]$): Origin reliability (e.g. Direct user = 0.95, Web scrape = 0.60).
- Interpretation Confidence ($C \in [0.0, 1.0]$): Model parsing certainty.
- Composite Weight:
  $$W_{\text{belief}} = T_{\text{source}} \times C_{\text{interp}}$$

5.2 Competing Hypotheses DAG
If two interpretations have comparable confidence:
$$\Delta = |C_1 - C_2| < 0.20$$
- The engine does NOT collapse the ambiguity.
- Both hypotheses are linked in a DAG: `H2.competing_with = H1.interpretation_id`.
- Flags `requires_clarification = True`.
- Transmitted to the Thought Engine so it can choose to ask a clarifying question rather than make a false assumption.

5.3 The Anti-Hallucination Invariant
Regardless of how high $C_{\text{interp}}$ is (even $C = 0.99$), an inferred proposition remains classified as `HYPOTHESIS`. Inferences can only be promoted to `FACT` through explicit confirmation or ground-truth evidence.

6. SOURCE PROVENANCE, TRUST CALIBRATION & INVERTIBLE SPAN MAPPING
================================================================================

Every extracted fact, entity, and proposition maintains a complete lineage chain:
$$\text{Claim / Entity} \xrightarrow{\text{spans}} \text{TextSegment} \xrightarrow{\text{OffsetMap}} \text{NormalizedInput} \xrightarrow{\text{rawRef}} \text{RawInputReference}$$
- Downstream engines can inspect the exact raw byte offsets that led to any extraction.
- Provenance distinguishes:
  * `USER_DIRECT`: Directly stated by the user.
  * `TOOL_OUTPUT`: Generated by an integrated tool or web lookup.
  * `INFERRED_BY_DIVA`: Derived internally by Perception or Thought engines.

7. CONTEXT RESOLUTION & WORKING MEMORY READ INTERFACE
================================================================================

The Perception Engine maintains a strict **read-only** contract with the `WorkingMemoryManager`:
- Call: `working_memory.get_recent_context(session_id, window_turns=5)`
- Returns:
  * List of recent dialogue turns with timestamps.
  * Active focal entities and pronouns.
  * Unresolved user questions.
- Elliptical Recovery: If user responds with *"In Tokyo"*, Context Resolver links it to the prior turn question (*"Where was your company founded?"*) and produces the elliptical proposition `[Company] -> [FOUNDED_IN] -> [Tokyo]`.

8.1 Memory Engine Envelope (`MemoryPerceptionEnvelope`)

8.3 Emotion Engine Envelope (`EmotionPerceptionEnvelope`)
- Verbatim text content.

8.4 Social Cognition Envelope (`SocialCognitionPerceptionEnvelope`)
- Interpersonal speech acts (promises, boundary assertions, praise, blame).
- Person entities and candidate social relationship links.

8.5 Learning Engine Envelope (`LearningPerceptionEnvelope`)
- Out-of-vocabulary terms and domain-specific technical jargon.
- Explicit user corrections to prior beliefs (*"Actually, I moved last year"*).

8.6 Feedback Engine Envelope (`FeedbackPerceptionEnvelope`)
- End-to-end processing latency breakdown (ms).
- Model inference times, component warnings, fallback activations.

9. STATE MACHINE, LIFECYCLE & EPHEMERAL BUFFER LEASES
================================================================================

9.1 State Machine
```
[RECEIVED] -> [VALIDATED] -> [NORMALIZING] -> [EXTRACTING] -> [INTERPRETING]
      │             │               │                │               │
      └──(Fail)─────┴────(Fail)─────┴────(Degrade)───┴───(Fail)──────┴─> [FAILED/DEGRADED]
                                                                              │
                                       [COMPLETED] <── [DISPATCHED] <─────────┘
```

9.2 Ephemeral Buffer Management (Zero Disk Leak)
- Active inputs reside in an in-memory dictionary: `_active_leases: dict[UUID, InFlightContext]`.
- As soon as delivery acknowledgments are received from Memory and Thought engines, the lease is released.
- Safety eviction timer purges any orphaned input after 60 seconds.
- Perception Engine NEVER writes raw messages to persistent disk; persistent retention is exclusively owned by Memory Engine.

================================================================================
10. ERROR RECOVERY, GRACEFUL DEGRADATION & IDEMPOTENCE
================================================================================

10.1 Tiered Graceful Degradation
- Tier 1 (NER Model Crash/Timeout):
  * Fall back to Regex + Gazetteer matching.
  * Tag extraction with `method = 'REGEX_FALLBACK'` and confidence `0.50`.
- Tier 2 (Working Memory Read Timeout):
  * Proceed without context; mark all pronouns `UNRESOLVED`.
  * Deliver payload flagged as `DEGRADED_NO_CONTEXT`.
- Tier 3 (Total Parser Crash):
  * Package raw normalized text into a `FALLBACK_RAW_ENVELOPE` directly to Memory and Thought engines so Diva can still converse.

10.2 Idempotence & Deduplication
- Compute hash: $H = \text{BLAKE2b}(\text{raw\_payload} + \text{session\_id})$.
- If an identical hash arrives within 2 seconds:
  * Drop immediately as `DUPLICATE_INGRESS_DROPPED`.
  * Return previous event reference without re-executing pipeline.

11. MODALITY EXPANSION SPECIFICATION (AUDIO, VISION, VIDEO)
================================================================================

11.1 The Modality-Independent Protocol
All future modality processors implement `BaseModalityProcessor`:
```python
class BaseModalityProcessor(ABC):
    @abstractmethod
    async def process(self, raw_bytes: bytes, metadata: dict) -> InputEvent: ...
    @abstractmethod
    async def extract_entities(self, event: InputEvent) -> list[ExtractedEntity]: ...
```

11.2 Multi-Modal Pipelines
- Audio Processor:
  * Whisper ONNX transcribes audio $\to$ `NormalizedInput`.
  * Acoustic prosody extractor produces pitch, energy, and speech rate $\to$ `EmotionPerceptionEnvelope`.
- Vision Processor:
  * Scene OCR extracts visible text $\to$ `NormalizedInput`.
  * YOLO/DETR detects objects and bounding boxes $\to$ `ExtractedEntity(type='OBJECT')`.
- Downstream Independence:
  * The Memory, Thought, and Emotion engines receive the exact same `EngineOutputPackage` schemas regardless of whether the input was spoken, typed, or seen.

12. FINAL ACCEPTANCE CRITERIA VERIFICATION REPORT
